## 🔓 卡片 1：加密格式解锁

**一句话**：把网易云 `.ncm`、QQ 音乐 `.mflac`/`.mgg`/`.qmc*` 等 30+ 种加密音频，一键解密为标准 FLAC/WAV。

| 支持平台 | 格式 | 解密方式 |
|---|---|---|
| 网易云音乐 | `.ncm` | AES-128-ECB + KeyBox XOR 流 |
| QQ 音乐 | `.mflac` 及 `mflac0/1/a/h/l/m` | 三种流密码自动分流 |
| QQ 音乐 | `.mgg` | 同上 |
| QQ 音乐 | `.qmc0` ~ `.qmc8` | 同上 |
| QQ 音乐 | `.qmcflac`、`.qmcogg` | 同上 |
| QQ 音乐 | `.tkm`、`.bkc*` 等 | 同上 |

**输出格式三选一**：
- 🟢 **自动（推荐）**：保留内层原始格式，无损重封装
- 🟡 **强制 FLAC**：统一 FLAC 容器
- 🔵 **强制 WAV**：统一 WAV 容器

> ⚠️ 有损内层（MP3/OGG）转 FLAC/WAV 只是**换容器，不提升音质**，界面会明确提示。

**关键原则**：源文件**只读不动**，输出撞名加序号 `(1)`，绝不覆盖原文件。

## 🗝️ 卡片 2：QQ 音乐密钥导入

**一句话**：新版 QQ 音乐 `.mflac` 密钥不在文件里？一键从运行中的 QQ 音乐客户端提取登录态，按歌换密钥。

**你需要做的**：
1. 打开 QQ 音乐客户端
2. 登录下载过这些歌的 VIP/付费账号
3. 点「导入 QQ 音乐密钥」
4. 等进度跑完

**技术链路**（全自动，无需你关心）：

```
识别 musicex 尾部 → 查本地密钥库 → 无命中则扫描 QQMusic.exe 内存
→ 提取 cookie → 调腾讯官方接口换密钥 → 双键落盘缓存
```

**安全设计**：
- ✅ cookie 用 **Windows DPAPI 加密**落盘，仅当前用户可解
- ✅ **只读内存扫描**，不修改 QQ 音乐任何数据
- ✅ 密钥**不上传**，全部本地存储
- ✅ 实测 **7/7 成功率**，失败自动重试一轮
- ✅ 内置**图文教程**，手把手教

## 🏷️ 卡片 3：联网自动补标签

**一句话**：musicex 文件本身不带歌名/歌手/封面？解锁后自动从官方接口取回，内嵌到输出文件。

**补齐内容**：
- 🎵 歌名、歌手、专辑名
- 🖼️ 500×500 专辑封面（内嵌到 FLAC/MP3）
- 🧹 文件名自动清理 `_EM`/`_EG` 等音质尾缀

**技术细节**：
- 按 `song_mid` 调**官方详情接口**（非搜索接口，避免搜错歌）
- 中文标签走 **ffmetadata1 文件 + UTF-8 编码**，绕开 Windows 命令行乱码
- 失败**静默降级**为无标签输出，不影响解锁本身

**可关闭**：解锁窗口提供开关（默认开），勾选关闭即走纯离线解锁。

## ⚡ 卡片 4：流式解密

**一句话**：300MB 文件只占用 76MB 内存，内存占用与文件大小解耦。

| 对比项 | 旧方案 | v1.1.0 流式方案 |
|---|---|---|
| 处理方式 | 整个文件读进内存 | **8MB 分块**流式处理 |
| 300MB 文件峰值内存 | ~890 MB | **~76 MB** |
| 内存/文件比 | ~300% | **~25.6%** |

**实测数据**（296.2 MB「大石碎胸口.ncm」）：
- 峰值内存：**75.9 MB**
- 进度回调：36 次（296MB / 8MB）
- 进度单调性：递增收尾 100% ✅

**技术要点**：
- NCM：分块 XOR，keystream 按流内绝对偏移计算，跨块连续
- QMC：三种流密码只依赖绝对偏移，天然支持随机访问分块
- 临时文件原子 rename + `finally` 兜底清理

## 📊 卡片 5：六维评分体系

**一句话**：不只告诉你"真假"，还给你 6 个维度的量化评分。

| 维度 | 含义 | 好 FLAC 的标准 |
|---|---|---|
| 🎚️ 位深 | 采样精度 | 16bit 或 24bit |
| 📈 采样率 | 每秒采样次数 | ≥44.1kHz（CD 标准） |
| 🔪 -60dB 截止频率 | 高频衰减点 | ≥20kHz |
| 🌊 动态范围 DR | 响度起伏 | 越高越好（古典乐常 >12） |
| 🔗 立体声相关性 | 左右声道相似度 | 因曲而异，参考值 |
| ⛰️ 峰值 | 最大响度 | 接近 0dBFS 但不削波 |

双击扫描结果的任意一行，弹出详情窗口，6 个指标全部展示。

## 🔍 卡片 6：三条假无损判定规则

**一句话**：满足任意一条，直接判假，可信度 >95%。

| 规则 | 检测什么 | 为什么能判假 |
|---|---|---|
| 🔥 **断崖检测** | 15kHz 以上频谱突然掉下去 30dB | MP3/AAC 编码器砍掉高频的物理痕迹，真无损不可能出现 |
| 🔪 **截止频率 < 16kHz** | -60dB 点低于 16kHz | CD 抓轨真无损一般在 20kHz 以上，低于 16kHz 说明高频被大幅阉割 |
| 🎭 **24bit 但 DR < 4** | 标称高规格但动态范围极低 | 16bit 强行封装成 24bit，位深造假 |

**判定逻辑**：
- 判**假** → **排除法**：出现了有损编码的物理痕迹 → 一定不是真无损（>95% 可信）
- 判**真** → "没找到假证据"（~85-90% 可信，极少数 640kbps AAC 转 FLAC 可能漏网）

## 🔄 卡片 7：批量扫描

**一句话**：拖一个文件夹进去，递归扫描所有子文件夹，几千首歌几分钟出结果。

**支持格式**：FLAC / APE / WAV / AIFF / MP3 / M4A / OGG / WMA / AAC / OPUS

**扫描特性**：
- 🧵 默认 **8 线程**并发（可调）
- 🌲 递归子文件夹
- 🚫 自动排除 `_待清除` 和 `*_安全输出` 目录
- 📂 支持**拖拽**文件夹到窗口

**结果表格**：
- 🟢 **● 真无损** — 绿色，放心听
- 🔴 **○ 假无损** — 红色，悬停看判假原因
- ⚠️ **! 分析失败** — 文件损坏或 ffmpeg 读不了

## 📝 卡片 8：智能重命名

**一句话**：按鉴定结果自动给文件名加标记，旧标记自动剥离，防止套娃。

**操作示例**：

| 原文件名 | 重命名后 |
|---|---|
| `周杰伦 - 晴天.flac` | `周杰伦 - 晴天 [真无损].flac` |
| `林俊杰 - 江南 [高音质].flac` | `林俊杰 - 江南 [假无损].flac` |
| `陈奕迅 - 十年 [真无损] [高音质].flac` | `陈奕迅 - 十年 [真无损].flac` |

**特性**：
- ✅ 自动剥离旧的 `[真无损]`/`[假无损]` 等标记，防止套娃
- ✅ 同步改同名的 `.lrc` 歌词文件
- ✅ `.cue` 文件不动（避免破坏索引）
- ✅ **预览 → 确认 → 执行**，三步操作，不直接改

## 🗑️ 卡片 9：智能去重

**一句话**：曲库里重复的歌，即使文件名完全不同，也能揪出来。

**两路去重**：

**路 A：同名对比**
- `周杰伦-晴天.flac`
- `周杰伦_晴天.FLAC`
- `周杰伦 晴天.flac`
→ 规范化后识别为同一首

**路 B：内容签名去重（硬核算法）**
- 即使文件名完全不同，只要这四项匹配就认为是同一首歌：
  - ⏱️ 时长（容差 0.3 秒）
  - 🌊 动态范围 DR（容差 0.2 dB）
  - 🔗 立体声相关度（容差 0.01）
  - 🔪 -60dB 截止频率（容差 50 Hz）
- 使用**并查集**算法，1000 首歌 < 1 秒完成

**清除操作**：
- 不要的文件移到 **`_待清除/`** 文件夹（**不是永久删除**）
- 生成 **`.restore_map.json`** 记录操作，支持一键还原

**一句话**：按音频文件里藏的 metadata（ID3 / Vorbis Comment），把乱七八糟的文件名规范化。

- 批量整理下载的音乐资源

## 📋 卡片 11：歌单导入

**一句话**：粘贴网易云歌单链接，自动从你曲库里挑出对应歌曲，建文件夹。

**支持方式**：
- 🔗 **网易云链接**：公开歌单**零登录全量解析**
- 📄 本地 `.md`/`.csv`/`.txt` 歌单文件
- ✏️ 手动粘贴歌名列表

**匹配逻辑**：
1. **精确匹配**：歌单里的 `"歌名 - 歌手"` vs 曲库文件的 title/artist tags
2. **模糊匹配**：歌单歌名是否出现在某个文件名中（规范化后 ≥2 字符才匹配，防误配）

**操作是复制，不是移动**——原曲库结构不动，歌单文件夹里是副本。

## 🛡️ 卡片 13：安全模式

**一句话**：新手保护开关——所有写操作变"复制"，原文件不动。

**开启后效果**：
- 重命名 → 复制到 `<文件夹名>_安全输出/` 并重命名
- 去重清除 → 复制到 `_待清除/`，原文件保留
- 歌单导入 → 复制到歌单文件夹

**建议**：第一次用 SonicCheck，先开安全模式试几次，确认操作符合预期再关。

## ❌ 卡片 14：协作式取消

**一句话**：扫描或解锁过程中，随时点"停止"，不残留临时文件，不卡死。

**支持取消的操作**：
- ✅ 批量扫描（每个文件分析前检查取消标志）
- ✅ 格式解锁（流式循环每块检查 + ffmpeg Popen 轮询 kill）
- ✅ 密钥导入（逐首 + 提取登录态前检查）

**取消语义**：
- 取消 **≠** 失败
- 不产生错误行
- 自动清理所有临时文件和半截输出

**旧 bug 已修**：v1.0.x 解锁时关窗口会假死最长 2 分钟，v1.1.0 已彻底解决。

## 👁️ 卡片 15：源文件只读 + 临时文件零容忍

**一句话**：你的原文件永远不会被碰，临时文件永远有兜底清理。

**源文件保护**：
- 🔒 解锁/鉴定**全程只读**原文件
- 🔒 输出一律撞名加序号 `(1)`，**绝不覆盖**
- 🔒 安全模式下所有写操作变复制

**临时文件管理**：
- 🧹 转码产生的临时 WAV：`try/finally` 保证删除
- 🧹 解锁裸流临时文件：原子 rename + `finally` 兜底
- 🧹 启动时自动清扫 1 小时前的残留（防崩溃后堆积）

> 这个设计来自一个惨痛教训：早期版本曾出现 **82.7GB 临时文件泄漏**。v1.1.0 对临时文件是零容忍的。
