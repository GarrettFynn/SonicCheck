## 你听过"假无损"吗？

本人爱搜集各类无损资源并享用（主要是通过下载各平台的mflac、ncm然后用魔法保存成flac格式），于是渐渐的搜集了几百G的FLAC，某天用 foobar2000 一看频谱——16kHz 之后直接一刀切。血压拉满 😅

**什么是假无损？**

文件确实是 `.flac` 格式，但源头是从 MP3 转过来的。FLAC 只是"容器"，里面的音频早就被有损压缩阉过了。假无损听起来和真无损完全不一样，但以前没有趁手的工具批量查，只能一首首手动看频谱，累死人。

所以我自己写了一个——**SonicCheck（声鉴·曲库管家）**。拖一个文件夹进去，自动帮你把所有音频扫一遍，真无损标绿，假无损标红，还会告诉你"为什么是假的"。

## 🔍 它怎么知道一首歌是假的？

直接说原理。你可以把这玩意当成"MP3 编码的物理痕迹检测"。

### 有损压缩会"吃掉"高频

MP3 为了把文件压小，会利用"人耳对高频不敏感"这个特点，把 20kHz 以上的信息全部砍掉，16kHz~20kHz 也大幅衰减。这是编码器干的，不是音质差，是**物理层面的信息丢失**。

关键来了：如果你把 MP3 转成 FLAC，FLAC 不会损失数据，但它只能保存 MP3 里**已有的**数据。MP3 已经砍掉的高频，不会因为转成 FLAC 就"长回来"。

所以假无损的 FLAC 文件，频谱会在某个频率点突然断掉——就像悬崖一样。真无损的频谱是平滑的，逐渐衰减的。

### 三个铁律（满足任意一条即判假）

**① 断崖检测** 🔥 最重要

在 15kHz 以上的高频区，如果频谱出现"悬崖"——相邻两个频率窗的能量落差超过 30dB，而且悬崖后面直接掉到 -70dB 以下没声了——这就是典型的 MP3/AAC 编码痕迹。真无损不可能出现这种情况。

**② -60dB 截止频率 < 16kHz**

从最高频率往低频扫，找到能量第一次跌到 -60dB 的那个点。CD 抓轨的真无损，这个值一般在 20kHz 以上。如果低于 16kHz，说明高频信息被大幅阉割了，大概率是 MP3 转的。

**③ 24bit 但动态范围 DR < 4**

有些不良资源会把 16bit 音频强行封装成 24bit（体积变大显得更"高级"），但实际动态范围还是 16bit 水平。标称 24bit 但 DR 测出来不到 4，就是位深造假。

## ✅ 可信度有多高？（重点）

这是大家最关心的问题：你说它假，我就信吗？

### 判"假"的可信度：> 95%

**断崖检测是物理层面的硬证据**。频谱在 16kHz 处突然掉下去 30dB，这不是主观评价，是客观数据。真正的无损音频不可能出现这种情况——CD 的 Nyquist 频率是 22.05kHz，真无损的频谱应该平滑延伸到 20kHz 以上。

换句话说，软件判"假"的逻辑是**"排除法"**：如果出现了有损编码特有的物理痕迹，那它一定不是真无损。这个逻辑是严密的。

### 判"真"的可信度：~85-90%

如果没检测到断崖、截止频率正常、DR 正常，软件会标"真无损"。这个判定的意思是：**"我没找到任何假无损的证据"**。

但这不等于 100% 保证。极少数情况可能漏网：
- 从 640kbps AAC（接近无损）转的 FLAC，断崖不明显
- 人为用音频软件伪造频谱（民间资源里极其罕见，因为这么做没意义）
- CD 母带本身高频就不丰富

**实际意义**：如果你的曲库有 1000 首歌，软件挑出 50 首假无损，这 50 首你可以非常放心地处理掉。剩下的即便有极个别漏网，对整体曲库质量影响微乎其微。

| 判定结果 | 可信度 | 说明 |
|---|---|---|
| 判假 | > 95% | 物理硬证据，几乎不会冤枉 |
| 判真 | ~85-90% | "没找到假证据"，极少数漏网 |
| 分析失败 | — | 文件损坏或 ffmpeg 读不了 |

## 📖 使用教程（5 步上手）

### Step 1：下载

GitHub 下载（推荐，速度最快）：
👉 https://github.com/GarrettFynn/SonicCheck/releases/tag/v1.0.0

或者直接发邮件找我要：
📧 feifeifynn@qq.com

下载后解压，得到 `SonicCheck.exe` 和几个文件夹。

### Step 2：装 ffmpeg（必须）

SonicCheck 自己不会读 FLAC，它需要 ffmpeg 帮它"翻译"成原始音频数据。这是唯一需要你手动装的东西。

**最简单的方法**：

1. 打开 https://www.gyan.dev/ffmpeg/builds/
2. 下载 `ffmpeg-release-essentials.zip`
3. 解压，把里面的 `ffmpeg.exe` 和 `ffprobe.exe` 两个文件
4. 放到 `SonicCheck.exe` 同级的 `resources/ffmpeg/` 文件夹里（没有就新建一个 `ffmpeg` 文件夹）

完事。不需要改环境变量，不需要命令行。

> 不会装的话发邮件给我，我把 ffmpeg 一起打包发你。

### Step 3：拖文件夹扫描

打开 `SonicCheck.exe`，把你想扫描的音乐文件夹**拖到窗口上**，或者点"选择文件夹"按钮。点"开始扫描"，等它跑完。

它会递归扫所有子文件夹里的 FLAC / APE / WAV / AIFF。默认 8 线程，几千首歌几分钟就完。

### Step 4：看结果

扫描完会出一个表格，每一行是一首歌：

- **● 真无损** — 绿色状态，放心听
- **○ 假无损** — 红色状态，鼠标悬停看原因
- **! 分析失败** — 文件损坏或读不了

双击某一行可以看这首歌的所有分析指标（DR、截止频率、峰值等）。

### Step 5：批量操作

扫完以后可以干很多事：

**导出 CSV** — 一键导出扫描结果，Excel 直接打开，文件名带时间戳

**智能重命名** — 自动给文件名加 `[真无损]` / `[假无损]` 标记，旧标记会自动剥离防止套娃

**去重** — 曲库大了难免有重复，支持"同名对比"和"内容签名去重"（即使文件名完全不同也能揪出来）。不要的文件移到 `_待清除/` 文件夹（不是永久删除，可以还原）

**标签改名** — 按音频文件的 metadata（歌名/歌手标签）规范化文件名，适合整理从网上扒拉的乱七八糟的文件名

**歌单导入** — 粘贴网易云歌单链接，自动从你曲库里把对应歌曲挑出来建文件夹。公开歌单不需要登录就能全量解析

**安全模式** — 左下角勾选后，所有写操作变成"复制"而不是"直接改"，原文件不动。新手建议先开这个试几次，确认没问题再关
