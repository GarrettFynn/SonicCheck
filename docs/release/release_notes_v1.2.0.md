# SonicCheck v1.2.0 发布说明

> 本版在 v1.1.0（无损鉴定 + 曲库管理 + 格式解锁）基础上，完成一轮全项目代码审查驱动的**性能、安全与正确性加固**：修复一个 v1.1.0 就存在的启动崩溃与一个可能删错歌的去重误报路径，万级曲库与批量解锁的响应速度大幅提升。**建议所有 v1.1.0 用户升级。**

---

## ⚠ 重要修复（升级理由）

- **启动崩溃（v1.1.0 存量 bug）**：扫描过文件夹后重启程序会直接崩溃
  （恢复"上次文件夹"时读到未初始化的扫描调度器）。本次打包冒烟抓到并修复。
- **去重误报加固（宁漏勿错）**：无标签文件此前按文件名分组即判重复——
  不同专辑的 `01.flac`（轨号命名）会被误判，批量确认后**移走的是不同的歌**。
  现在纯文件名撞车必须内容签名复核通过才合并；轨号/超短名不参与名字合并；
  分析指标全为兜底值的坏文件不再互相"合并"。有标签的分组不受影响。
- **QQ 登录 cookie 永不明文落盘**：DPAPI 加密不可用时旧版会静默把登录态
  明文写进本机文件；现在宁可不入库并明确弹窗告知（密钥本身正常保存）。

## 🚀 性能与响应

- **万级曲库不再卡界面**：结果表格改为批量渲染（插行/回填从 O(n²) 降为
  O(n)，3000 行实测 0.13 秒；旧版开始扫描时界面冻结分钟级）
- **解锁并行化**：批量解锁最多 4 线程并行，总吞吐约 4 倍；输出命名加了
  并发保护，同名文件并行解锁不再互相覆盖
- **网易云歌单解析后台化**：千首歌单解析不再冻结界面（旧版网络差时
  "未响应"可达 1 分钟），显示"已获取 N/M 首"进度，可随时取消
- **解锁窗口选文件夹后台扫描**：大曲库不再冻结数十秒；先按扩展名过滤
  再读文件头，IO 减少 90% 以上；损坏的 .ncm 不再被静默忽略
- **批量解锁网络熔断**：断网时不再逐首白等超时（旧版 100 首最坏可拖
  半小时），连续 3 次失败自动暂停联网补标签，解锁本身不受影响

## 🛡 稳定性与安全

- QQ 密钥导入的内存扫描不再跳过大内存区域（修复偶发"未找到登录信息"），
  ctypes 调用全部补齐类型声明（64 位句柄截断隐患）
- 密钥库写入失败不再被静默吞掉，弹窗提示"密钥仅本批有效"
- 扫描信号显式跨线程投递；空文件夹扫描不再锁死界面；ffmpeg 定位加缓存
  （万级曲库省 2 万次 PATH 扫描）；日志正确转义 ffmpeg 错误输出中的尖括号

## 🎵 歌单与文件名

- 修复 `01 - 晴天 - 周杰伦` 这类最常见歌单行格式解析错乱（编号被当成歌名）
- GBK 编码的歌单 txt 不再整单乱码（自动回退 GB18030）
- 歌单复制遇跨子目录同名歌曲自动加序号（同名曲不同音质不再静默丢歌）
- 文件名超长自动截断、Windows 保留名（CON/NUL/COM1 等）自动处理

## 🧪 工程

- 测试套件入库并上线 GitHub Actions CI（128 项断言，含 CI 环境编码兼容）
- 仓库结构整理：宣发物料/发布说明/开发日志归档到 `docs/` 子目录
