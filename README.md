# 声鉴·曲库管家 SonicCheck（原 AudioQuality Scanner）

面向 HiFi 爱好者的 Windows 桌面工具：批量鉴定本地音乐是"真无损"还是"假无损"，声纹去重、规范命名、按歌单整理，并生成可分享的频谱证据报告。

[![License: GPL v3](https://img.shields.io/badge/License-GPLv3-blue.svg)](https://www.gnu.org/licenses/gpl-3.0)
[![Python](https://img.shields.io/badge/python-3.10+-blue.svg)](https://www.python.org/)
[![PyQt6](https://img.shields.io/badge/PyQt6-6.6+-green.svg)](https://www.riverbankcomputing.com/software/pyqt/)

> **当前版本 v2.0.0**。近期三个版本的主线：
> - **v2.0** 架构升级：结果表格迁移 Model/View——**扫描进行中即可排序/筛选**，2 万行插入约 1 秒、排序底层 4ms；主窗口拆分业务控制器；推送版本 tag 自动 CI 打包；启动时静默检查新版本。
> - **v1.4 引擎能力**：**声纹指纹去重**（chromaprint，识别改名/不同音质/live 变体）；**疑似升频提示**；**CLI 无头模式**（`--scan` 批量鉴定不打开窗口）。
> - **v1.3 可视化**：**频谱图**（详情/对比对话框，断崖与截止线直接标注）；**HTML 证据报告**（每首假无损一张内嵌频谱的"证据卡"，可直接发送）；统一设置面板；表格搜索与状态记忆。
>

## 快速开始

### 方式一：绿色版（推荐）

从 [GitHub Releases](https://github.com/GarrettFynn/SonicCheck/releases) 下载 `SonicCheck_v2.0.0_win64.zip`（约 176MB），**解压即用**——ffmpeg 已内置，目标机器无需安装 Python。

### 方式二：源码运行

```bash
git clone https://github.com/GarrettFynn/SonicCheck.git
cd SonicCheck
pip install -r requirements.txt
python main.py
```

运行需要 ffmpeg/ffprobe：放 `resources/ffmpeg/` 下（打包前），或装入系统 PATH。

### 方式三：命令行批量鉴定（不打开窗口）

```bash
SonicCheck.exe --scan D:\Music --out report.html
# 可选：--threads 8 --seconds 30 --out report.csv
```

## 使用指南

### 1. 扫描曲库

把音乐文件夹**拖进窗口**（或点"选择文件夹"）→ 点**开始扫描**。程序递归扫描子文件夹，逐首解码分析（默认 8 线程、每首分析前 30 秒，均可在左栏或"设置"调整）。

- 扫描**进行中**就能排序、搜索、筛选结果（v2.0 起不再冻结）
- 随时点**停止**，协作式取消不残留临时文件；未扫完的行标记"已取消"
- 左栏"最近 ▾"下拉可快速切回扫过的文件夹

结果表五列：文件名 / 评分 / -60dB 截止 / DR / 状态（● 真无损 ● 假无损 ! 失败）。

### 2. 看懂结果

- **状态列**：鼠标悬停显示判定原因（如"频谱在 15800Hz 处断崖式截断"）与疑似升频提示
- **双击任意行**：详情窗口——完整元数据 + **频谱曲线**（见[人工二次判断](#人工二次判断指南)）
- **搜索框**：按文件名/路径/标签歌名/歌手实时过滤，可与"只看真/假无损"叠加；右键菜单支持"只看此歌手/此格式"一键筛选
- **同名对比**：左侧选组、右侧"指标 × 文件"对比表；恰好两首时下方叠加双频谱曲线

### 3. 生成证据报告

点**导出报告(HTML)**：单文件自包含报告（汇总卡片 + 明细表 + 每首假无损的"证据卡"——判定原因 + 内嵌频谱图），无外链、断网可看、可直接发微信/QQ。**导出CSV** 则输出全列数据（UTF-8-BOM，Excel 直接打开），含"疑似升频"列。

### 4. 曲库管理

| 功能 | 入口 | 说明 |
|---|---|---|
| **智能重命名** | 一键重命名 | 按判定加 `_真无损`/`_假无损` 后缀（可在设置自定义标记文本与前/后缀位置），自动剥旧标记防套娃；同 stem 的 .lrc 跟随改名 |
| **标签改名** | 标签改名 | 按 ID3/Vorbis 标签规范化为 `歌名-歌手` 或 `歌手-歌名` |
| **同名对比 / 去重清除** | 去重清除 | 三路识别重复：标签 / 内容签名（时长+DR+相关度+截止频率）/ **声纹指纹**（勾选"启用声纹比对"，可发现改名、不同音质、live 变体，组标注相似度）。被清除项移入 `_待清除/`（可"还原清除"一键移回），确认无误后手动删除 |
| **歌单导入** | 歌单导入 | `.md/.csv/.txt` 歌单、手动粘贴、或**网易云链接零登录解析**；匹配的文件复制到以歌单名命名的新文件夹，未匹配清单自动写入剪贴板 |
| **格式解锁** | 格式解锁… | 网易云 `.ncm`、QQ 音乐 `.mflac/.mgg/.qmc*` 等解锁为标准格式。源文件只读；NCM 自动提取标签与封面；QQ 新版 musicex 文件点"导入 QQ 音乐密钥"（从运行中的客户端提取登录态换密钥，本机缓存不上传），解锁后可联网补齐标签与封面。注意 QQ STag 文件密钥不在文件内无法离线解锁；请仅转换你合法获得的文件 |

### 5. 安全模式与设置

勾选左栏**安全模式**：所有写操作（重命名/去重/歌单）变为复制到 `<文件夹名>_安全输出/`，原文件零改动——首次使用建议开启。

右上角**设置**统一管理：线程数、每首分析时长、默认安全模式、质量标记文本与位置、检查更新开关；与左栏双向同步。

### 6. 更新检查

启动 3 秒后后台查询 GitHub Latest（8 秒超时，失败静默），有新版时在日志与状态栏提示，仅提示不自动下载；设置里可关闭。

## 真假无损判断原理

### 什么是"假无损"

把 MP3/AAC 等有损文件直接改名/封装成 FLAC/WAV，就是假无损——文件变大了，但音质损失已经不可逆地发生。有损编码器基于心理声学模型，会**砍掉人耳不敏感的高频**（通常 16kHz 以上）：这段频谱在编码时被丢弃，转成"无损"容器也不会回来。频谱上的这种**硬截断**是有损出身无法抹除的指纹。

### 程序怎么判：三条假无损规则

每个文件先统一转码为 48kHz/32bit PCM（修复不同容器的测量偏差），取前 30 秒做 FFT 频谱分析与时域统计，然后：

1. **频谱断崖**：在 15kHz–0.95×Nyquist 区间内，若相邻频窗落差 >30dB 且断崖后 50 个频点的平均能量 <-70dB，视为断崖；断崖频率 <20kHz 时判假无损——这是有损编码最直接的证据
2. **-60dB 截止频率 <16kHz**：能量衰减到 -60dB 的最高频率点过低，说明高频内容物理性缺失
3. **24bit 但 DR <4**：位深标记 24bit 却几乎没有动态范围，典型"有损源升频重采样再标 24bit"的造假特征

三条任一命中即判**假无损**，全部未命中判**真无损**。命中原因会写入状态列提示与报告证据卡。

### 六维评分（0-100，量化质量）

| 维度 | 满分 | 评分标准 |
|---|---|---|
| 位深 | 15 | ≥24bit 得 15；≥16bit 得 10；其余 5 |
| 采样率 | 10 | ≥96kHz 得 10；≥48kHz 得 8；其余 5 |
| -60dB 截止 | 25 | ≥20kHz 得 25；≥18k 得 20；≥16k 得 15；≥12k 得 10；其余 5 |
| 动态范围 DR | 25 | ≥12dB 得 25；≥8 得 20；≥5 得 15；≥3 得 10；其余 5 |
| 立体声相关 | 15 | (1-|相关度|)×15——单声道伪装立体声/过度相关会失分 |
| 峰值电平 | 10 | 峰值在 -3~-1dB 最优得 8（适当响度）；过响得 3（疑似削波）；较低得 10 |

假无损总分再 **-20**。评分是"质量量化"，判定是"真伪结论"，两者独立——**评分高不代表一定是真无损**（320kbps MP3 也可能拿高分），请以下方频谱判读为准。

### 已知局限（诚实声明）

- **高码率有损（≥256kbps）痕迹较弱**：320kbps MP3 的截止常在 20kHz 以上、断崖不明显，自动判定可能漏检——这正是需要[人工二次判断](#人工二次判断指南)的原因
- **老录音/黑胶转制天然高频少**，可能被误判为假无损——看频谱形态（自然渐变衰减 vs 硬直线截断）可区分
- 疑似升频提示（96kHz 采样但截止 <20kHz 等）**仅供参考**，不参与判定与评分

## 人工二次判断指南

程序给出初判后，最有说服力的复核方式是**亲眼看频谱**。v1.3 起这不需要任何外部工具。

### 第一步：看频谱图（双击结果行）

详情窗口底部的频谱曲线，横轴是对数频率（1k/10k 网格线），纵轴 0～-100dB：

- **真无损（CD 来源）**：频谱能量自然延伸到 20kHz 以上，高频段呈**渐变、毛刺状衰减**——那是乐器泛音与录音底噪的自然形态
- **假无损（有损出身）**：频谱在某频率**戛然而止**，形成一条垂直的"悬崖"，断崖之上只剩编码噪声的零星毛刺。程序会用**红色虚线**标出断崖位置，**黄色实线**标出 -60dB 截止——两线重合并靠近 16-19kHz，基本可以锤证

### 第二步：对照截止频率经验表

不同码率的有损编码，截止频率大致如下（编码器不同略有浮动）：

| 来源 | 典型截止频率 | 断崖可见度 |
|---|---|---|
| 128kbps MP3/AAC | ~16kHz | 极明显，必被抓 |
| 192kbps MP3/AAC | ~17-18kHz | 明显 |
| 256kbps MP3/AAC | ~19kHz | 可见 |
| 320kbps MP3 | ~20-20.5kHz | 微弱，**最难判**，需结合 DR 与试听 |
| CD 无损 (44.1k/16bit) | 自然延伸至 21-22kHz | 无断崖，自然衰减 |
| 老录音/黑胶转制 | 可能天然只有 15-18kHz | **有衰减但形态渐变**，易误判 |

### 第三步：对比同曲不同版本

"同名对比"里选恰好两首的组，下方叠加双频谱（青/橙双色）：同内容不同音质的曲线在低中频几乎重合、高频段分道扬镳——截止位置低的那条就是有损出身。

### 第四步：导出证据留存

"导出报告(HTML)"的证据卡把判定原因与频谱固化成单文件，方便存档或向资源发布者举证。

### 判读口诀

> **一看断崖有无，二看截止高低，三看衰减形态（硬截断=假，渐变=真），四查 DR 与位深匹配（24bit 但 DR<4 必有诈），高码率存疑时信频谱形态、别只信分数。**

## CLI 无头模式

```text
用法: SonicCheck.exe --scan <目录> [--threads N] [--seconds N] [--out 路径]

  --scan     要扫描的音乐文件夹（必填）
  --threads  并行线程数（默认 8，与 GUI 一致）
  --seconds  每首分析秒数（默认 30，与 GUI 一致）
  --out      输出文件：.csv 或 .html（默认 ./SonicCheck报告_时间戳.csv）
```

不创建任何窗口；NAS/定时任务场景可直接脚本化调用。默认参数与 GUI 严格一致，同一目录产出相同判定。

## 算法来源与致谢

- **判定口径**：频谱断崖作为有损编码痕迹，源自 Hydrogenaudio 论坛社区共识与 What.CD 时代的检测实践；截止频率阈值与 DR 容差经真实曲库样本校准。判定/评分代码自 v1.0 起口径冻结，历次版本仅做附加扩展，保证跨版本结论可比。
- **DR 计算**：参考 DR Meter（3 秒块 RMS 取最响 5 块均值的相反数）。
- **声纹指纹**：chromaprint（AcoustID 项目）经 ffmpeg 内置 muxer 采集；比对算法（全字倒排 + 汉明距离滑移）为本项目实现。
- **解锁算法**：逐字节对照 unlock-music CLI v0.2.12 参考实现；QQ 密钥内存扫描移植自 qmdec（MIT）。
- **ffmpeg**：gyan.dev 构建（full + essentials）。
